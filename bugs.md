This is a user-maintained list of bugs. User puts stuff in, user removes. Agents may annotate with a resolution. User will verify.

| Bug Description | Resolution |
|-----------------|------------|
|Missing ability to select which unit is active (blinking) with the mouse.| Fixed. A press-and-release on the same map tile used to only re-centre the view when a unit was already selected, so there was no way to activate a different one. Both click paths now share `game_map_click_dispatch` (game_loop.c): own colony → open it, own units → activate one (stack chooser for several), else move the tile cursor. |
|On colony founding, a large swath of fog is revealed. It looks like Coronado's bonus is applied even without him.| Fixed — it *was* Coronado's bonus. DOS `FUN_364b_1dd6` runs `for n in 0..3: if has_ff(n, 6) then FUN_13f1_00a6(colony, n)`; the port called the ±5 reveal unconditionally. `colonies_reveal_founded` now takes the col1 save and reveals only for nations that own FF 6, which is also every Coronado owner, not just the founder. Unit-tested both ways. |
|Units loaded onto ships are shown in the transport view in colonies. They should not be; no non-transports should be in that view. Two more problems: 1. Units are only actually loaded when a ship leaves. While in the colony, it's not yet decided whether a unit will leave with a ship. 2. On bringing a loaded unit into a colony, they are automatically disembarked and have no orders (and can move if they had any moves left to begin with).| Fixed. The colony hold strip no longer draws passenger sprites — goods only. Docking now puts everyone ashore on *every* arrival path, not just an explicit player move: `units_try_move` disembarks a transport's passengers whenever it enters a friendly colony, with no orders and their remaining moves intact. Loading stays a departure-time decision — the pre-existing `units_board_sentries_from_tile` already boards the sentried units on the tile when a ship leaves. |
|Population view does not display food shortages properly. It just colors the food production number red. What it should be doing is putting the shortage in the same resource counter as the food surplus (only surplus or shortage is ever shown, never both, often none if all food is consumed). | Fixed. The net-food counter now appears whenever `food_net != 0`: a surplus as before, a shortage as the same counter with the grey food icon and a red number. The fish/grain production pair is no longer recoloured and no longer swaps to grey — production reads as production. Nothing is drawn when the colony eats exactly what it grows. |
| Missionary action to Establish Mission is missing from enter village popup. | Partly addressed — could not reproduce the disappearance itself. The row gating in `ai_contact_enqueue_village_meet` matches `indian_actions_menu.md` row 3 and the existing unit test still shows the row for a Missionaries-type unit at a mission-free village. Two real defects in that gate were fixed: (a) the menu re-derived *which* village it was describing from "some village of this tribe next to the unit", so with two villages adjacent, or none, it could read a different village's mission state — callers that already know the settlement now pass its index (`ai_contact_try_village_meet_unit_at`); (b) the "has a mission" test was `!= 0xff`, while DOS tests the byte as signed (`+5 < 0` = none). If you still see it missing, the village/tribe state at that moment would pin it down. |
| Indian alarm isn't shown. In DOS, it's a number of exclamation marks of varying colors drawn on top of the village graphic on the map. | Implemented. `map_panel_render_tribes_on_map` now draws 1–3 exclamation marks above each visible village. The tier and colours are DOS's (`FUN_112b_0790`): the DS:0x54f6 grudge word `>> 5` clamped 0..3, forced to 3 once `alarm_by_player` passes 0x4a, coloured 10/11/14/12 by tier. Since few writers feed that table in the port yet, the lower tiers are also graded off `alarm_by_player` at DOS's own 0x19/0x32/0x4b cuts. Mark shape and placement are the port's, not decoded from DOS — worth a look against the original. |
| When a new Founding Father joins congress, after the initial popup, view should change to the second page of the Continental Congress report, and after that to the colonizopedia entry on that founding father. | Fixed. The arrival OK now carries the elected index (`nation_b`); dismissing it opens the Continental Congress report on page 2, and closing that opens that father's Colonizopedia article. |
| "Iroquis accept conversion at Jamestown" is a bizarre popup I've never seen. Conversion is done by establishing a mission in a village, and then sometimes indians come to a colony and spawn a convert in the colony. Also, a village with a mission that is attacked can spawn converts. Check DOS for details. | Fixed. That popup came from an invented per-turn pulse where a human's Missionary standing next to a village silently established a mission and announced it; first contact also handed out a free mission. Both removed for the human — the pulse is now the AI's stand-in only, and the player establishes missions through the @ACTIONS menu. The real event is ported from `FUN_5bfb_022e` (viceroy_unpacked.c:96989): a Brave from a settlement holding your mission walks up to one of your colonies and, at `rng(0,15) < tech + 2` (doubled for a Jesuit mission), an Indian Convert appears in that colony with GAME.TXT @INDIANSCONVERT naming it. Attacked-mission converts (@INDIANSLAVES) are still unported. |
| When SoL membership reaches 50% there's a persistent popup with a choice to rebel or not. I've not seen this in DOS, except maybe at 100%. That popup is normally only shown when the player selects game->Declare Independence. It should not be shown unless you can show that DOS spawns it spontaneously at some threshold of SoL. | Fixed — could not show it, because DOS does not. `FUN_43f7_2564` has no call site anywhere in the decompile; it is reached only from the MENU.TXT @GAME "DECLARE INDEPENDENCE" command. The per-turn check no longer raises the confirm for a human at any SoL; the SoL≥min auto-declare is kept only for the headless/AI path, where nobody can answer a dialog. |
| Clicking anywhere while in a multiple-choices popup selects the current one. It should do nothing instead. Only clicking one of the two options should be considered a choice. | Fixed. On a CHOICE dialog only a click on an option row decides anything; clicks on the body, the chrome, or outside the dialog are swallowed. ESC and right-click still cancel. |
| "Tea Party" never actually happens the "Tea" part is always substituted by some actual cargo Colony models. | Fixed. GAME.TXT's `{%STRING3 Party}` is built by `FUN_38fd_3dc8` as colony name + " " + cargo name, so it reads e.g. "Jamestown Tobacco Party!"; the port hardcoded `%STRING3` to "Tea". Now built the same way and used for @TAXOPTIONS' "Hold '… Party.'" row, the @TEAPARTY body, and the popup title. |
| Clicking the map, even a colony, ends the turn if the End of Turn marker in the sidebar is active. Only clicking the sidebar should then be considered an end of turn press. Clicking a colony should almost always be considered as an instruction to open up the colony UI. | Fixed. The map-viewport End-of-Turn confirm is gone; a click there keeps its normal meaning (open a colony, activate a unit, start a go-to). Only the right-hand sidebar click confirms the turn. |
| "Throwing away excess cargo" should never happen just from filling up from production. If a colony produces more goods than its stores allow, that's normally ignored. Every 100 units of a cargo is reason for a "colony has a new load of <cargo> available" popup instead (gated behind the appropriate notification setting). | Fixed, and it matches DOS exactly. `FUN_364b_0688` reports a loss only for the part of the overflow that predates this turn's production (`if (production < overflow)`); either branch ends clamped at capacity, so production overflow is a silent clamp with no @SPOIL. Losses under 2 tons are dropped and Food is exempt. @CARGOREADY* is now its own event rather than an else-branch of spoilage, fires on every 100-unit crossing (not once per campaign), skips Food, and is gated only on the "report new cargos available" option — the once-per-campaign latch belongs to the separate @TUTORIAL6 hint, which is now emitted too. |
