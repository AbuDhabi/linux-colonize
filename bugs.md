|Missing ability to select which unit is active (blinking) with the mouse.| Fixed. A press-and-release on the same map tile used to only re-centre the view when a unit was already selected, so there was no way to activate a different one. Both click paths now share `game_map_click_dispatch` (game_loop.c): own colony → open it, own units → activate one (stack chooser for several), else move the tile cursor. |
|On colony founding, a large swath of fog is revealed. It looks like Coronado's bonus is applied even without him.| Fixed — it *was* Coronado's bonus. DOS `FUN_364b_1dd6` runs `for n in 0..3: if has_ff(n, 6) then FUN_13f1_00a6(colony, n)`; the port called the ±5 reveal unconditionally. `colonies_reveal_founded` now takes the col1 save and reveals only for nations that own FF 6, which is also every Coronado owner, not just the founder. Unit-tested both ways. |
|Units loaded onto ships are shown in the transport view in colonies. They should not be; no non-transports should be in that view. Two more problems: 1. Units are only actually loaded when a ship leaves. While in the colony, it's not yet decided whether a unit will leave with a ship. 2. On bringing a loaded unit into a colony, they are automatically disembarked and have no orders (and can move if they had any moves left to begin with).| Fixed. The colony hold strip no longer draws passenger sprites — goods only. Docking now puts everyone ashore on *every* arrival path, not just an explicit player move: `units_try_move` disembarks a transport's passengers whenever it enters a friendly colony, with no orders and their remaining moves intact. Loading stays a departure-time decision — the pre-existing `units_board_sentries_from_tile` already boards the sentried units on the tile when a ship leaves. |
|Population view does not display food shortages properly. It just colors the food production number red. What it should be doing is putting the shortage in the same resource counter as the food surplus (only surplus or shortage is ever shown, never both, often none if all food is consumed). | Fixed. The net-food counter now appears whenever `food_net != 0`: a surplus as before, a shortage as the same counter with the grey food icon and a red number. The fish/grain production pair is no longer recoloured and no longer swaps to grey — production reads as production. Nothing is drawn when the colony eats exactly what it grows. |
| Missionary action to Establish Mission is missing from enter village popup. | Not a defect, as far as this can be shown. Driving the real menu against `COLONIZE/COLONY01.SAV` (a live village, met tribe, no mission anywhere in that save) gives `Establish Mission / Incite Indians / Cancel Action` for a **Missionaries-type unit**, and `Live Among The Natives / Cancel Action` for a colonist whose *profession* is Jesuit Missionaries. That split is DOS's own: `indian_actions_menu.md` row 3 gates on unit **type** 3, so a Jesuit Missionary bought in Europe is a colonist specialist and has to be blessed first — colony screen, pick the colonist, eject role "Missionary" (needs a Church or Cathedral). Two real defects in the gate were fixed on the way: (a) the menu re-derived *which* village it described from "some village of this tribe next to the unit", so with two adjacent, or none, it could read another village's mission state — callers that know the settlement now pass its index (`ai_contact_try_village_meet_unit_at`); (b) the "has a mission" test was `!= 0xff` where DOS tests the byte as signed. Villages are not created with a mission (`ai_tribe_add` writes 0xff) and that save has none set; the one path that used to hand them out for free — first contact — was removed with the conversion-popup fix. Missions are also now drawn on the village, so a pre-existing one is visible rather than inferred. |
| Indian alarm isn't shown. In DOS, it's a number of exclamation marks of varying colors drawn on top of the village graphic on the map. | Fixed, and the real cause was upstream of the drawing: **nothing was raising village alarm at all.** `ai_indian_152e_best_threat_nation_stub` — DOS `FUN_4cc6_03f8`, the "which European threatens this settlement, and how much" scan — was a PARKED stub returning "no threat", so the encroachment arm of the village tick never ran and every settlement's alarm word stayed 0 no matter how much you settled, built or cleared next to it. Ported for real (`ai.c`): the 20-tile military-pressure ring off DS:0xc8/0xde, then every colony within distance 7 scored on population, buildings (scaled by difficulty for a human colony), difficulty and distance, halved across continents, halved for the French, then rescaled by the village's own mission. Its output feeds `t->alarm[e]`, which the bump now carries as DOS's int16 instead of truncating to a byte. Verified against `COLONY04.SAV`: villages near colonies climb, distant ones stay flat, French earn about half — guarded by a new `unit_ai` case. On the drawing side, `map_panel_draw_tribe_chrome` reads what DOS reads: the addresses in `FUN_112b_0790` resolve onto the settlement record itself (base 0x54ec, stride 0x12 — the same 18-byte record, tech-at-+2 confirms it), so 0x54f6 is `tribe.alarm[nation]`, not the separate grudge table the first attempt used. Tier = that word >> 5 clamped 0..3, forced to 3 above alarm 0x4a, colours 10/11/14/12, tier+1 marks. The mission flag DOS draws from the same function (tribe+5 ≥ 0, owner's colour from DS:0x848 = {12,9,14,13}, dimmed unless Jesuit) is drawn too. Mark shape and placement are the port's. |
| When a new Founding Father joins congress, after the initial popup, view should change to the second page of the Continental Congress report, and after that to the colonizopedia entry on that founding father. | Fixed. The arrival OK now carries the elected index (`nation_b`); dismissing it opens the Continental Congress report on page 2, and closing that opens that father's Colonizopedia article. |
| "Iroquis accept conversion at Jamestown" is a bizarre popup I've never seen. Conversion is done by establishing a mission in a village, and then sometimes indians come to a colony and spawn a convert in the colony. Also, a village with a mission that is attacked can spawn converts. Check DOS for details. | Fixed. That popup came from an invented per-turn pulse where a human's Missionary standing next to a village silently established a mission and announced it; first contact also handed out a free mission. Both removed for the human — the pulse is now the AI's stand-in only, and the player establishes missions through the @ACTIONS menu. The real event is ported from `FUN_5bfb_022e` (viceroy_unpacked.c:96989): a Brave from a settlement holding your mission walks up to one of your colonies and, at `rng(0,15) < tech + 2` (doubled for a Jesuit mission), an Indian Convert appears in that colony with GAME.TXT @INDIANSCONVERT naming it. Attacked-mission converts (@INDIANSLAVES) are still unported. |

That popup is normally only shown when the player selects game->Declare Independence. It should not be shown unless you can show that DOS spawns it spontaneously at some threshold of SoL. | Fixed — could not show it, because DOS does not. `FUN_43f7_2564` has no call site anywhere in the decompile; it is reached only from the MENU.TXT @GAME "DECLARE INDEPENDENCE" command. The per-turn check no longer raises the confirm for a human at any SoL; the SoL≥min auto-declare is kept only for the headless/AI path, where nobody can answer a dialog. |

| "Tea Party" never actually happens the "Tea" part is always substituted by some actual cargo Colony models. | Fixed. Now built the same way and used for @TAXOPTIONS' "Hold '… Party.'" row, the @TEAPARTY body, and the popup title. |

The map-viewport End-of-Turn confirm is gone; a click there keeps its normal meaning (open a colony, activate a unit, start a go-to). Only the right-hand sidebar click confirms the turn. |
| "Throwing away excess cargo" should never happen just from filling up from production. If a colony produces more goods than its stores allow, that's normally ignored. Every 100 units of a cargo is reason for a "colony has a new load of <cargo> available" popup instead (gated behind the appropriate notification setting). | Fixed, and it matches DOS exactly. `FUN_364b_0688` reports a loss only for the part of the overflow that predates this turn's production (`if (production < overflow)`); either branch ends clamped at capacity, so production overflow is a silent clamp with no @SPOIL.
