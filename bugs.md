|Missing ability to select which unit is active (blinking) with the mouse.| Fixed. A press-and-release on the same map tile used to only re-centre the view when a unit was already selected, so there was no way to activate a different one. Both click paths now share `game_map_click_dispatch` (game_loop.c): own colony → open it, own units → activate one (stack chooser for several), else move the tile cursor. |
|On colony founding, a large swath of fog is revealed. It looks like Coronado's bonus is applied even without him.| Fixed — it *was* Coronado's bonus. DOS `FUN_364b_1dd6` runs `for n in 0..3: if has_ff(n, 6) then FUN_13f1_00a6(colony, n)`; the port called the ±5 reveal unconditionally. `colonies_reveal_founded` now takes the col1 save and reveals only for nations that own FF 6, which is also every Coronado owner, not just the founder. Unit-tested both ways. |
|Units loaded onto ships are shown in the transport view in colonies. They should not be; no non-transports should be in that view. Two more problems: 1. Units are only actually loaded when a ship leaves. While in the colony, it's not yet decided whether a unit will leave with a ship. 2. On bringing a loaded unit into a colony, they are automatically disembarked and have no orders (and can move if they had any moves left to begin with).| Fixed. The colony hold strip no longer draws passenger sprites — goods only. Docking now puts everyone ashore on *every* arrival path, not just an explicit player move: `units_try_move` disembarks a transport's passengers whenever it enters a friendly colony, with no orders and their remaining moves intact. Loading stays a departure-time decision — the pre-existing `units_board_sentries_from_tile` already boards the sentried units on the tile when a ship leaves. |
|Population view does not display food shortages properly. It just colors the food production number red. What it should be doing is putting the shortage in the same resource counter as the food surplus (only surplus or shortage is ever shown, never both, often none if all food is consumed). | Fixed. The net-food counter now appears whenever `food_net != 0`: a surplus as before, a shortage as the same counter with the grey food icon and a red number. The fish/grain production pair is no longer recoloured and no longer swaps to grey — production reads as production. Nothing is drawn when the colony eats exactly what it grows. |
| Missionary action to Establish Mission is missing from enter village popup. | Diagnosed from `port_saves/missionary_bug.SAV`: the unit at (46,23) is a proper Missionaries-type unit, and the village to the north (tribe 50 at (46,22)) already carries `mission = 0x00` — **the human's own mission**. Tribe 37 at (47,27) too. With the mission already yours, DOS lists neither Establish Mission (needs no mission) nor Denounce Heresy (needs a *rival's*), leaving exactly the Incite / Cancel pair you saw — so the menu is right and the save data is wrong. Those two are stale: they were written by the pre-fix build, whose first-contact arm and human missionary-adjacency pulse both handed missions out for free. Verified there is no live writer left — 80 Indian turns on a mission-free save with the human as nation 0 create none — and that the save round-trip preserves the byte exactly, so nothing is corrupting it now. The converts arriving at Jamestown follow from the same stale data: tribe 50 genuinely holds your mission, so the (correct) @INDIANSCONVERT event fires. The two bogus missions are baked into that save and the port has no "abandon mission" action; say the word and I'll clear them into a copy. Earlier findings below still stand. |

| Indian alarm isn't shown. In DOS, it's a number of exclamation marks of varying colors drawn on top of the village graphic on the map. | Fixed, and the real cause was upstream of the drawing: **nothing was raising village alarm at all.** `ai_indian_152e_best_threat_nation_stub` — DOS `FUN_4cc6_03f8`, the "which European threatens this settlement, and how much" scan — was a PARKED stub returning "no threat", so the encroachment arm of the village tick never ran and every settlement's alarm word stayed 0 no matter how much you settled, built or cleared next to it. Ported for real (`ai.c`): the 20-tile military-pressure ring off DS:0xc8/0xde, then every colony within distance 7 scored on population, buildings (scaled by difficulty for a human colony), difficulty and distance, halved across continents, halved for the French, then rescaled by the village's own mission. Its output feeds `t->alarm[e]`, which the bump now carries as DOS's int16 instead of truncating to a byte. Verified against `COLONY04.SAV`: villages near colonies climb, distant ones stay flat, French earn about half — guarded by a new `unit_ai` case. On the drawing side, `map_panel_draw_tribe_chrome` reads what DOS reads: the addresses in `FUN_112b_0790` resolve onto the settlement record itself (base 0x54ec, stride 0x12 — the same 18-byte record, tech-at-+2 confirms it), so 0x54f6 is `tribe.alarm[nation]`, not the separate grudge table the first attempt used. Tier = that word >> 5 clamped 0..3, forced to 3 above alarm 0x4a, colours 10/11/14/12, tier+1 marks. The mission flag DOS draws from the same function (tribe+5 ≥ 0, owner's colour from DS:0x848 = {12,9,14,13}, dimmed unless Jesuit) is drawn too. Mark shape and placement are the port's. |

Now built the same way and used for @TAXOPTIONS' "Hold '… Party.'" row, the @TEAPARTY body, and the popup title. |
| Clicking the map, even a colony, ends the turn if the End of Turn marker in the sidebar is active. Only clicking the sidebar should then be considered an end of turn press. | "Throwing away excess cargo" should never happen just from filling up from production. If a colony produces more goods than its stores allow, that's normally ignored. Every 100 units of a cargo is reason for a "colony has a new load of <cargo> available" popup instead (gated behind the appropriate notification setting). | Fixed, and it matches DOS exactly. `FUN_364b_0688` reports a loss only for the part of the overflow that predates this turn's production (`if (production < overflow)`); either branch ends clamped at capacity, so production overflow is a silent clamp with no @SPOIL. Losses under 2 tons are dropped and Food is exempt. @CARGOREADY* is now its own event rather than an else-branch of spoilage, fires on every 100-unit crossing (not once per campaign), skips Food, and is gated only on the "report new cargos available" option — the once-per-campaign latch belongs to the separate @TUTORIAL6 hint, which is now emitted too. |
| Indians begging for food ask for 0 food. They never do than in DOS. | Fixed. GAME.TXT's accept row is `"We offer you {%NUMBER0} of our {%NUMBER1 food} as a sign of friendship."` and the port set neither number, so both rendered 0 — and the choice rows were handed to the popup straight from the catalog without any token substitution at all. NUMBER0 is now exactly what accepting hands over and NUMBER1 the colony's whole store, both read from one `ai_contact_beg_food_gift` helper so the label and the effect cannot drift apart, and the rows go through `popup_msg_apply_tokens`. A `unit_ai_contact` case drives the real trigger and asserts the row reads 25 of 100 with no stray token. |
| Converts are shown with their proper graphic in colony UI, but as free colonists on the overland map. | Fixed. DOS has one icon rule for both views: `FUN_112b_0060` routes *every* @UNIT type 0 (Colonists) unit through `FUN_112b_0002(profession)`, whose jump table (CS:0x14, case 8) sends profession 0x1b to icon 0x43 — sprite 66 here, exactly the one `units_job_icon_sprite` already returned for the colony screen. `units_map_sprite` skipped that branch and fell through to the bare @UNIT icon. It now consults the profession table for an unequipped Colonists-type unit; the equipment cases still come first, standing in for DOS's own `type != 0` overrides. Guarded by a `unit_units` case. (Two entries in that table disagree with the same DOS jump table and were left alone as out of scope: profession 23 should be 104 not -1, and 24 should be 61 not 77.) |
| Cargo Party ie. boycotting a good should always pick a cargo the selected colony has. You can't dump 0 tons of something in protest. | Fixed, and DOS agrees. `FUN_38fd_3dc8` fills `aiStack_cc[c]` with the largest stock of cargo c across the human's colonies and skips every cargo whose entry stayed 0, both when summing the roulette weights and when walking them. The port had keyed the candidate mask off Europe's *bid* instead, so it could name a good no colony was storing — and its last-resort fallback then widened to literally every cargo. The mask now comes from actual colony stock; the Europe price stays the weight; the fallback drops only the boycott exclusion, never the stocked one. `unit_ai_king` now stocks the warehouse for the roulette cases and adds one asserting that empty stores mean no boycott and a standing hike. |
| Mission icon on Indian villages should be a cross, of a color dependent on nation and missionary skill. Check DOS. It's not an exclamation mark. | Fixed — it is a cross, and the colour rule is nation plus Jesuit. Ghidra drops the register arguments to `FUN_1b9e_000a` (the rect fill: colour and height on the stack, x in AX, y in DX, width in BX), so the geometry came out of the raw instruction stream at CODE_5:112b:0afd..0b8c — a 5x6 black pad, a 1x4 vertical bar at pad+2 and a 3x1 horizontal bar at pad+1 one row down. Colour is the owning nation's from DS:0x848 = {12, 9, 14, 13}, less 8 for a plain mission and full brightness for a Jesuit one (`CMP CX,1; SBB AL,AL; AND AL,0xf8` is -8 exactly when the 0x10 bit is clear). The cross sits just right of the alarm marks, on the same baseline. |
| Indian alarm icon, the exclamation mark, should be centered, and I'm pretty sure the colors are a bit wrong vs DOS. | Fixed; the whole thing now comes off the disassembly rather than a reading of the decompile. Position is DOS's fixed anchor — first mark at tile_x+6, baseline tile_y+4, each mark stepping 2px (they overlap, being 3px wide) — instead of the previous centred row whose width drifted with the count. Each mark is a 3x7 surround, a 1x5 coloured bar inset (1,1), then one surround-coloured pixel four rows down splitting it into stem and dot. The **count** was wrong too: it is not the alarm tier but the threat score — the loop seeds a counter with `FUN_281f_0316`'s out value and subtracts 4 per pass while it stays >= 0, so `score/4 + 1` marks — and nothing at all is drawn when no nation scores. Colours 0x0a / 0x0b / 0x0e / 0x0c by tier were right, but the final mark is dimmed by 8 whenever that counter has fallen to 2 or less, which was missing; and when the threat is a *different* European, DOS draws a single mark in that nation's own colour (DS:0x848) instead, telling you who they are angry at — also missing. `ai_indian_village_threat` is now public so the renderer reads the same scan the turn tick does (single-pass over the unit pool, cheap enough per visible village per frame). `unit_map_panel` asserts the exact pixel geometry of both the mark and the cross. |
| Name new world popup fails to stop execution until it is resolved, like other popups. | Fixed together with the turn-processing row below. DOS runs every popup as a blocking call, so the code behind one simply does not run until it is answered; here dialogs are asynchronous, so `game_after_unit_action` kept going after `game_try_prompt_landho` opened the @LANDHO name entry — handing control to the next unit (and, with the End of Turn option off, ending the turn) from behind the prompt. Every automatic hand-off now asks `game_turn_flow_allowed` first and parks itself instead (`game_defer_turn_flow`); `game_update` replays the parked hand-off once the map is back on screen with nothing over it. |
| Returning a ship to Europe immediately opens the European Status. It should not. Ships ARRIVING in Europe should open the status screen. Check DOS for details. | Fixed. ORDERS → Return to Europe had its own copy of the sail-away code ending in `game_try_enter_europe`; the H command and the Go-To-onto-a-lane path (`game_ship_sail_to_europe`) never did that. All three now share that one helper, so ordering a ship home only puts it in the Expected lane. The screen opens on *arrival*, where DOS opens it: `europe_tick_voyages` moves the ship Expected → Harbor and raises `open_on_dock`, which `game_finish_end_turn` acts on. |
| Founding Father pedia pages are missing background (should be wood), and the pallette is messed up too. | Fixed, and the two halves had different causes. **Background:** the Colonizopedia *article* view cleared to black — only the category list blitted `WOODPANL.PIK` — so every article, not just a Father's, drew on bare black; the panel is now blitted for articles too. **Palette:** the article view fell through to the map palette. `CC-00..24.SS` are all indexed against `CCBKGD.PIK`'s palette, which differs from WOODPANL's on 45 of the 96 indices a portrait uses (measured) — flesh went black and the outlines magenta.
