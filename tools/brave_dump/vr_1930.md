## Result — `dump_1930_2` (v3 hang)

**Hang fired.** Live thunk `@0x22858` = `EB FE 0D 30 19 EA 16 18 00 00`
(`CS` aliases `2042:2430` ≡ `224A:03B0`).

| Item | Value |
|------|-------|
| `IP` | `0x03B0` (hang) |
| `[SS:SP]` | **`CC81:1B87`** |
| `[SS:SP+4]` | `0000` (looks like indian **slot 0**) |
| `DS:5394` | `3` (still Euro; hang before 1816 body) |
| BP chain | all `1930:1554` (overlay return vector) |

**Caller read:** `CC81:1B87` is the same linear address as `CC89:1B07` in the
loaded `4d56` image — last byte of `CALLF 2042:0934` (`FUN_281f_0934` exhaust)
inside the **1816 act-loop** region (`~1A8C…`). That is not a clean “year loop
→ thunk” edge (and there is **no** static `CALLF *:2430` in the dump).

So: thunk entry is live and takes `param=0`, but the far return on the stack
looks like **overlay/alias noise into 1816 itself**, not a recovered `130d`
caller. Year loop still only shows `CALLF 2042:0676` → `1b3a` for Indians.
